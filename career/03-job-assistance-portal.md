## Key concepts

### ATS resume
- **ATS** = Applicant Tracking System. Most resumes are read by software first.
- **Plain layout** — no columns, no images, no fancy fonts. Word/PDF saved with selectable text.
- **Standard sections**: Contact · Summary · Skills · Experience · Projects · Education · Certifications.
- **Bullets**: Action verb + what + how + impact (numbers!). "Built churn model improving retention 12%" beats "Worked on churn project."
- **Keywords**: mirror the job description. If they say "PySpark," your resume says "PySpark."
- **Length**: 1 page if <5 years experience, 2 max.
- **Tense**: past for past roles, present for current.

### Portfolio website
- Sections: Hero (who) · Projects (what) · About · Contact · (optional) Blog
- Each project: problem, approach, tech, screenshots, link to repo + live demo
- Hosted: Vercel / Netlify / GitHub Pages — free
- Domain: yourname.com if available
- Speed matters: keep images optimized, no heavy frameworks for a static site

## ATS resume checklist

- [ ] Single column, simple fonts (Arial, Calibri, Helvetica, Times)
- [ ] Saved as both .docx and .pdf
- [ ] Contact line: name, city/country, email, phone, LinkedIn URL, GitHub URL
- [ ] Summary: 2–3 lines, role-targeted
- [ ] Skills: comma-separated list, grouped (Languages / Frameworks / Tools / Cloud)
- [ ] Each experience bullet starts with a verb and ends with a metric
- [ ] No "References available on request"
- [ ] Run through a free ATS scanner (e.g., Resume Worded, Jobscan)

## Portfolio site checklist

- [ ] At least 3 quality projects featured
- [ ] Each project has its own page or section, not just a link
- [ ] Source code linked
- [ ] Mobile responsive
- [ ] Loads in <2s on 4G
- [ ] Custom favicon
- [ ] OG/meta tags so LinkedIn link previews look good
