# Module 3 — Build In Public

> **Duration**: 3h 04m 40s · 5 sessions
> **Status**: 🔒 Locked (next after Online Credibility)

## Why this module exists here (not later)

You've now started posting publicly (Module 2). You've put one or two projects on GitHub. The Build In Public module hardens that habit and teaches the **technical infrastructure** behind it — Git, GitHub, OSS workflow.

Without these, every project you make stays trapped on your laptop, and every "I want to contribute to open source" stays an aspiration.

## Curriculum (verbatim)

### Session 1 — What is Build In Public?
Philosophy + cadence + why it works.

### Session 2 — Getting Started with Git
Init repo, add, commit, status, log, .gitignore, branches.

### Session 3 — Fundamentals of Git Collaboration
Clone, fork, push, pull, merge, conflicts, rebase basics.

### Session 4 — Anatomy of GitHub Repository
README, Issues, Pull Requests, Projects/Boards, Actions, Releases, Wiki, Settings.

### Session 5 — Finding Opensource Projects to Contribute on GitHub
Where to look, how to read CONTRIBUTING.md, how to make a clean first PR.

## Module-level goal

After this module:
- I can explain Build In Public to a non-developer in 60 seconds
- Git is no longer scary — I can do init/branch/commit/merge/rebase reflexively
- I've made at least 1 OSS contribution (even a docs fix)
- My GitHub has a healthy commit graph
- I have a system for posting weekly without thinking
